## Wiki: User_manual/Reference/Gcodes.md (4)

_Carried from the range document:_

Cross-checked against every reviewed dictionary entry by batch-fetching all 138 commits' diffs via `gh api` and grepping for genuinely new parameter bullets, then verifying each candidate directly against the pinned RRF 3.7.0-rc.1 source (never trusting the wiki's prose alone). Real fixes this pass, all cited in `dictionary/commands.json` and covered by new tests in `test/diagnostics.test.ts`: M574 E (since 3.7.0-beta.3, commit 83403dfac6) and S5 (encoder stall detection, this baseline's own da53463f24); M558 V/U (load cell scale/preload window, since beta.3) and P type 3 removed just before rc.1 (b28569a1d5); M575 F (serial parity, since beta.2, 0a90c25e8a) and the previously-missing C (RS485 direction port, Modbus device mode); M584 P (visible axis count); M950's T rewritten to cover all three forms it silently serves (heater sensor number, LED strip type, spindle type 0/1), K similarly widened (LED colour order vs. spindle min:max:idle PWM - same letter, different meaning per sub-form), a new L (spindle min:max RPM), U (LED max length), and B corrected to since 3.7.0-beta.2 (see the Heating section's own note - this wiki cross-check is what caught that date being wrong); M116 P (colon list of tool numbers since beta.3, was a single number before); M308 widened with universal (A/U/V) and thermistor-specific (T/B/C/R/L/H) parameters, with a summary note documenting that other sensor types (thermocouple/BME280/68x/DHT/current-loop-pyro/thermopile) have their own further parameters deliberately not modelled; M106 widened with its thermostatic-fan form (T/H/B/L/X) and C (fan name) - a high-value fix given M106 appears in nearly every real print file; M569 R (found to allow -1 "always disabled", so its kind was also corrected from boolean01 to integer - boolean01 would have flagged R-1 as wrong-kind) and U (TMC5160/2160 current-scaler override); M906 T (idle timeout); M593 L (accepted but a deliberate no-op since 3.6.0, kept so old config.g files aren't flagged). Left undocumented, matching this task's established tier-1-scope precedent: brand-new commands the wiki added in this range that have no dictionary entry at all (M140.1, M581.1, M952, M953, M954, M959, M970/M970.3, M36.2, M505.1, M558.3, M558.4), and parameter additions on commands that were never reviewed to begin with (M107 F, M115, M118 P enum, M141, M404, M576, M582, M594, M667, M915, M916, M953, M997) - these remain draft-only or unreviewed by design, not gaps in this pass.
